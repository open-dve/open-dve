# UART agent - requirements

Each requirement: statement, source (doc/spec.md reference -> R1/R2/R3 there),
how it is verified. "submit" = `vrf/work/rlist/submit.list`; a test name
alone means its runs against the RTL (`uart_<x>`) and, where listed, the
slave agent (`uart_<x>_mem`, `uart_<x>_seq`). Coverpoints are in
`odve_uart_cg` (`src/agent/odve_uart_agent_pkg.sv`).

| ID | Requirement | Source | Verified by |
|---|---|---|---|
| REQ-UART-001 | Both data lines idle at mark (1). The master holds `txd` at mark from time 0 and for at least one bit time after reset before its first character. | spec §2, §3 (R3 convention) | Every receiver here (monitor, slave, RTL) waits for mark before a start bit; all submit runs. A lost first character would fail the scoreboard (`basic_test`, all runs). |
| REQ-UART-002 | A character starts with one start bit (space) of one bit time. | spec §3 (R1 §8.6.2) | Monitor/slave/RTL reject a start bit that is not space at its middle; scoreboard echo check in all submit runs. |
| REQ-UART-003 | 5, 6, 7 or 8 data bits are sent least significant bit first, and received in the same order. | spec §3 (R1 §8.6.2 LCR bits 0-1) | `format_test` (all word lengths, patterns 0x00/0xFF/0x55/0xAA/0x01/0x80), scoreboard echo comparison (`uart_format`, `uart_format_mem`); coverpoint `cp_bits`, `cp_data`. |
| REQ-UART-004 | Parity none, even, odd, mark (stick 1) and space (stick 0) are generated by every transmitter and checked by every receiver. | spec §3 (R1 §8.6.2 LCR bits 3-5) | `format_test` (every parity x word length): a wrong parity from either side is a monitor `uvm_error` (rxd) or a missing echo + DUT `st_pe` report (txd); `cp_par`, `x_bits_par`. |
| REQ-UART-005 | Stop bits: 1, or 1.5 with 5 data bits, or 2 with 6-8 data bits; the transmitter sends the full stop time. | spec §3 (R1 §8.6.2 LCR bit 2) | `format_test`, `b2b_test` (8E2), `baud_test` (5M1.5, 8E2): the monitor checks the second stop bit / second half of 1.5 on both lines (`uvm_error` "stop bit shorter"); back-to-back frames would collide otherwise; `cp_stop`, `x_bits_stop`. |
| REQ-UART-006 | A receiver checks only the first stop bit. | spec §3 (R1 §8.6.2) | **Not verified**: implemented in the RTL, slave and monitor, but no test sends a character whose second stop bit is space (it would also trip the monitor's stop-length check, which is the agent's own transmitter check). |
| REQ-UART-007 | A space shorter than half a bit (false start bit) does not start a character. | spec §4, §5 (R1 feature "False Start Bit Detection") | `err_test` (`uart_err`, `uart_err_mem`): >= 3 `GLITCH` items of 1..bit_clks/4 clocks; test checks the monitor counted >= 3 glitches (`n_glitch[0]`); the scoreboard fails on any echo or DUT status report they cause. |
| REQ-UART-008 | Receivers sample each bit at its middle with 16x oversampling and tolerate a transmitter rate offset of at least ±3 %. | spec §4 | `baud_test` (`uart_baud`, `uart_baud_mem`): master at 31 and 33 clk/bit vs 32 nominal (±3.1 %), back to back, 8E2 / 8N1 / 5M1.5; RTL, slave agent and monitor must all receive every character correctly (scoreboard). |
| REQ-UART-009 | Characters may follow each other back to back (next start bit right after the last stop bit). | spec §3 | `b2b_test` (`uart_b2b`, `uart_b2b_seq`), `baud_test`, `overrun_test`, `flow_test` send with no gaps; `cp_gap.back2back`. |
| REQ-UART-010 | A wrong parity bit is detected and reported as a parity error. | spec §5 (R1 §8.6.3 bit 2) | `err_test`: `bad_parity` injections; monitor flag `pe` (test requires >= 3), RTL `st_pe` paired with each by the scoreboard (`uart_err`); `cp_err.parity`, `x_dir_err`. |
| REQ-UART-011 | A first stop bit sampled as space is detected and reported as a framing error. | spec §5 (R1 §8.6.3 bit 3) | `err_test`: `bad_stop` injections; monitor `fe` (>= 3), RTL `st_fe` paired by the scoreboard; `cp_err.framing`/`par_fram`. |
| REQ-UART-012 | A line held at space for longer than a character time is a break: reported once (not as parity/framing error), and the receiver accepts the next character only after the line returns to mark and a valid start bit follows. | spec §5 (R1 §8.6.3 bit 4) | `err_test`: `BREAK` items of 14..24 bit times; monitor `brk` (>= 3), RTL `st_bi` paired (exactly one report per break, flags pe = fe = 0); following characters echoed correctly; `cp_err.brk`. |
| REQ-UART-013 | A character received with an error is discarded (not echoed by the device), and reception continues with the next good character. | spec §7 (device design) | `err_test` (`uart_err`, `uart_err_mem`): the scoreboard expects no echo for errored characters and the exact echo for all good ones; the test checks echoes == good characters. |
| REQ-UART-014 | A good character that arrives while the 8-entry receive FIFO is full is lost and reported as an overrun; the FIFO contents are unaffected. | spec §5 (R1 §8.6.3 bit 1) | `overrun_test` (`uart_overrun`, RTL only): 11 characters into a held-off device, exactly 3 `st_oe` reports (each paired with the character received at that time), the first 8 echoed intact. Any unexpected overrun in other tests is a scoreboard error. Slave agent overrun is implemented (`n_oe`) but **not verified** (no status pins). |
| REQ-UART-015 | Auto-CTS: with flow control on, a transmitter starts a character only while its CTS input is asserted (low); a started character is completed. | spec §6 (R2 §7.3) | `flow_test` (`uart_flow`, `_mem`, `_seq`): while the master holds `rts_n` high the peer (RTL or slave agent) must send nothing (test checks no `rxd` character); the master must have been held off by `cts_n` at least once (`n_cts_stall > 0`). |
| REQ-UART-016 | Auto-RTS: the receiver deasserts RTS when its FIFO holds DEPTH-1 characters and asserts it again when it drains, so a flow-controlled sender never overruns it. | spec §6 (R2 §7.2) | `flow_test`: the master stalls (above) and no overrun is reported (RTL: any `st_oe` is a scoreboard error), all 48 characters echoed. |
| REQ-UART-017 | The echo device returns every good character complemented within the data bits, in the same frame format and order. | spec §7 (device design) | Scoreboard in every submit run, against the RTL and the slave agent in both modes. |
| REQ-UART-018 | The link is full duplex: a character is received while the previous one is being sent back. | spec §2 | `b2b_test`, `baud_test`: back-to-back traffic keeps both lines busy at once; scoreboard checks both. |
| REQ-UART-019 | The monitor flags errors in characters from the peer (`rxd`: parity, framing, break, short stop, false start bit) as `uvm_error`. | spec §5 | Checker active in every submit run (none fired). **Negative test not run**: no test injects an error on `rxd` to prove the checker fires. |
| REQ-UART-020 | The slave agent, in MEM and SEQ mode, behaves like the RTL device as far as the master can observe (echo, error discard, flow control). | README "Roles and modes" | The same tests against `+uart_slave=mem` / `seq`: `uart_basic_mem/_seq`, `uart_format_mem`, `uart_b2b_seq`, `uart_baud_mem`, `uart_err_mem`, `uart_flow_mem/_seq`. |
| REQ-UART-021 | All stimulus randomness comes from `odve_rand` streams (same values for the same seed on both simulators). | comp/agents/README.md, comp/common/rand/README | `script/rand/rand_check.py odve/comp/agents/uart` exits 0. |
